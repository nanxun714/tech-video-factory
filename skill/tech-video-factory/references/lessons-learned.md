# 踩坑复盘：通用教训清单（2026-09-14 批量8条生产实战沉淀）

> 来源：一次批量生产 8 条视频的完整实战。每条 = 现象 → 根因 → 通用规则。
> 规则全部为通用写法，任何批量渲染/子代理协作/音视频管线都适用。配合 `quality-checklist.md` 使用。

---

## 一、动画时序类（本批 3 条片翻车的同一根因）

### 1. 叠化翻页的「边界帧空白」⭐ 本批最大坑，三连翻车
- **现象**：视频每个页面切换的那一帧（精确边界帧）画面只剩背景+字幕，内容全空。独立验收抽边界帧 → 直接判 fail。
- **根因**：旧页淡出窗口写在 `[len-10, len]`（页尾**之前**淡完），Sequence 又提前 10 帧开始——导致边界帧上旧页 opacity=0、新页元素还没到入场时间。任何一帧出现「旧页已消失、新页未画」都是事故。
- **通用规则**：
  - **不变量：交叉淡化的任何瞬间，画面上必须至少有一个完整主体。** 淡出窗口放在边界**之后**（`[len, len+10]`），旧序列向后延长而不是提前开始。
  - 序列改成 `from=start, dur=len+10`、页内 `off=0`（页内时序天然不变，元素 delay 不用重算）。
  - 修完只看一帧确认：抽**精确边界帧**（不是边界-1、-12）。

### 2. 抽帧自检的采样点设计缺陷（为什么三次自检都没发现边界帧空白）
- **现象**：实现者自检两三轮"全过"，独立验收一抽就翻车。
- **根因**：自检脚本抽的是「边界-1 / 边界-12 / 场景中点」，永远采不到边界帧本身。**采样点避开了所有故障位置。**
- **通用规则**：
  - 设计 QC 采样点前，先回答"这个动画在哪些帧上最脆弱"（边界帧、转场帧、循环周期边界、0:00、结尾卡），**脆弱帧本身必须进采样集**。
  - 抽帧脚本一旦发现过一种新故障模式，就把对应的帧位永久加进脚本（本批已加：精确边界帧）。

### 3. 「自检通过」≠「真的没问题」
- **现象**：子代理汇报"两轮抽帧逐张查看、QC 全部通过"，实际边界帧全空。
- **根因**：自检者和实现者是同一个（同一套采样、同一套假设），盲区共享。
- **通用规则**：**成片必须由独立一方用不同采样策略复验一次**（实现者自查 → 独立 judge 验收 → 修复 → judge 复验闭环）。judge 判 fail 时，把精确帧号+现象发回给实现者，修复后必须针对原帧位复验。

## 二、并行生产 / 子代理协作类

### 4. 并发额度限制（user concurrency limit exceeded）
- **现象**：一次派 4 个子代理，2 个直接被拒；后台任务也会被杀。
- **通用规则**：并发子代理控制在 **2~3 个**；被拒的任务原样重发即可，不是代码问题。

### 5. 被杀的 agent 可能已经把活干了一半
- **现象**：某 agent 报错失败，但组件代码已经完整落盘（只差渲染）。
- **通用规则**：**重做任何"失败"任务前，先看磁盘上已有什么**（文件行数/mtime/内容），失败的可能是"渲染前的最后一步"，直接续做能省一轮完整实现。

### 6. 多人（agent）共写一个注册表
- **现象**：8 个组件都要在 Root.tsx 注册 Composition，并行编辑必然冲突。
- **通用规则**：**共享文件的改动集中做在开工前**——先批量生成占位 stub（统一导出 `DUR` + 同名组件），一次性注册完；之后 agent 只许覆盖自己的组件文件、不碰 Root.tsx。`durationInFrames` 引用导入的 `DUR`，改时长自动同步。

### 7. 渲染用的代码可能不是你以为的代码
- **现象**：会话中断续跑后，tsx 可能在不可见续跑中被改过。
- **通用规则**：**渲染前对比 mp4 与 tsx 的 mtime**；改过 tsx 后用 Edit 前先重新 Read（file-state 冲突）。

## 三、TTS / 音频类

### 8. edge-tts 词级元数据时长虚高（实锤复现）
- **现象**：+15%/+18% 语速下，词级 Offset+Duration 算出的句长比实际语音长 8%~24%（本批 scale 实测 1.08~1.24）。
- **通用规则**：**句子时长一律以 mutagen 读 MP3 真实时长为准**；词级锚点按 `真实时长 / 元数据末尾` 等比缩放后再用（谁说到谁出现的对齐才能保住）。生成脚本：`public/audio/gen_batch8.py`（词级+实测双保险，可复用）。

### 9. edge-tts 偶发 NoAudioReceived / 空音频
- **通用规则**：合成必须带 5 次退避重试 + 文件大小校验（>1KB 才算成功）；批量生成时单句失败只重试该句。

## 四、布局 / 视觉类（老坑复发即警钟）

### 10. 页尾压轴元素停留不足
- **现象**：句子最后一个词触发的卡片/大字，弹入后不到 30 帧就翻页，等于白做。
- **通用规则**：压轴元素按词级锚点提前 3~5 帧给 delay，且**保证 ≥30 帧完整停留**（男声快语速时尤其要卡）。

### 11. 封面落款与底部字幕重叠
- **现象**：封面落款 y=942，字幕条上沿 ~986，44px 字幕的弹出位移盖住落款下半截。
- **通用规则**：画布底部 100px 是字幕专区；封面/结尾卡的一切文字落位前先查"该帧字幕窗口是否有内容、字幕条上沿在哪"。金句大字与字幕同句的解法依然是**金句时段不渲染 Subtitle**。

### 12. 跨片一致性
- **现象**：同一批 8 条片，角标有的「小秋」有的「全栈小秋」，被验收点名。
- **通用规则**：**批量生产前先定"系列规范表"**：角标文案、落款格式、字幕样式、色板、标签胶囊样式，写进每条片的任务书，验收时当检查项。

### 13. 老坑（每次都查，一行版）
- 绝对定位文字容器必须显式 width（否则竖排墨团）；裸 `<path>` 必须包 `<svg>`；flex 容器内禁 absolute SVG 箭头（会堆到原点）；第 0 帧必须完整封面（静态元素 delay=-99，禁入场动画）；字幕=旁白原话去标点；网络链路请求+响应双向；禁 emoji 品牌文字；红底白字恐吓大字报 = 已被数据否决。

## 五、流程 / 交付类

### 14. 交付物清单（发布日三件套）
- mp4（第 0 帧即封面，**不再单独做封面文件**）＋ 置顶评论文案（含合集导流、标签、文案第一行术语降级）＋ 发布顺序建议。
- 发布当天手动归集合集；每条结尾预告必须指向合集内下一条。

### 15. 批量生产的推荐编队（本批验证可行）
- **主线**：一次写完 8 条脚本+断句 → 一个批量 TTS 脚本（词级+实测）→ 批量字幕 → stub 预注册 → 子代理 2~3 个一波并行实现+自渲自检 → 独立 judge 按批验收 → 修复回炉 → 统一交付。
- **经验值**：单 agent 全包一条（实现+渲染+抽帧自检+修复）约 20~35 分钟；4 条一波并行约一轮 30 分钟。
- **必须保留的人工卡点**：音效音量是人估的，发布前人耳复听；可疑片子自己快进刷一遍。

### 16. 人眼目检抓不住「慢速叠化」——转场必须程序化断言（2026-09-14 batch10 补）⭐
- **现象**：HttpVsHttps 整条片 9 次页切换全是跨 10~20 帧的慢速叠化（违反铁律①），生产 agent 两轮逐帧目检 128 张全放行；主会话对全片做相邻帧 diff 扫描，10 秒抓到（全片无一处帧间 diff>8）。
- **根因**：叠化不产生「空白帧」「错位帧」，每张单看都"合理"——人眼逐帧看的是单帧质量，看不到**帧间关系**。声画错位（配音进下页、画面停上页）同样只存在于帧间。
- **通用规则**：**帧间关系类故障（叠化、ghost、跳帧）只能用相邻帧 diff 扫描抓，不能靠目检。** 交付前必跑 `scripts/qc_precheck.py`（边界 diff<4 = 无硬切，断言已内置）；实测阈值：硬切边界 diff 6~13，叠化 0~4。

### 17. cv2 随机 seek 在 Windows 会抽错帧（假空白冤案）
- **现象**：QC 用 `cap.set(CAP_PROP_POS_FRAMES, n)` 抽帧，892 边界被抽成"近空白"，顺序解码复验 891/892/893 全正常——差点引发一轮无意义返工。
- **通用规则**：**Windows 上 cv2 抽帧一律顺序解码挑帧**，禁用 POS_FRAMES 随机 seek。`qc_precheck.py` / `qc_auto.py` 已内置；自写抽帧脚本照抄这两个的读帧循环。

## 六、2026-09-14 用户反馈返工追加（结尾静音 + 手机画面感）

### 16. 结尾"没声只有画面"——BGM 素材本身太小声
- **现象**：用户反馈"进度条还剩 3~4 秒没有声音"。结尾卡区间测得 -73.8dB（数字静音）。
- **根因两层**：①结尾卡静置 3.3s 里唯一在响的是 bed.wav；②**bed.wav 文件本身 mean -56dB / max -49dB**——就算 volume 拉满也听不见。正片有人声撑着没暴露，结尾一静置就露馅。改组件里的音量参数（0.1→0.17）完全无效，白渲了一轮 8 条。
- **通用规则**：**接入任何音频素材前先 volumedetect 量一遍素材本体响度**；静置段（截图卡/结尾）的听觉主角不能指望一个 -50dB 的文件。修法：`ffmpeg volume=40dB,loudnorm` 生成 bed_outro.wav（mean -19dB），结尾段单独混入。
- **通用规则（后处理省渲染）**：成片只缺一段音频时，`ffmpeg amix + adelay + -c:v copy` 直接混进 mp4（视频流无损、秒级完成），同时把同样的 Sequence 补进源码保持一致。**惨痛细节：atrim 切出的段 amix 时从 t=0 开始对齐——不加 `adelay` 会把音乐混到片头而不是结尾**（第一版混音全混错了位置，幸好在验证环节抓住）。

### 17. 视觉验收只判"对不对"，没判"像不像"
- **现象**：手机卡顿/WiFi 片的手机是灰色占位线框（无画面感），judge 判 pass（因为没有溢出/空白等技术问题）；用户一眼打回。
- **根因**：judge 的检查表全是"技术正确性"，没有"主体是否具象、有没有被画成占位图"这条。同一批里 TCP/UDP 片的手机（深色机身+挖孔+侧键+完整短视频界面）是用户亲自改过的样板，两条新片没对齐这个标准。
- **通用规则**：**批量生产前把用户已点名的视觉样板列成"对齐清单"**（本账号已确认：手机=TCP/UDP 片那台的具体 App 界面画法），实现任务书和验收标准里都要有这条；judge 检查表加一条"主体元素是具象内容还是占位线框"。

## 七、2026-09-19 追加（尾部数字静音二次复发）

### 18. edge-tts mp3 尾部静音垫：拿文件时长当语音终点建轴 ⭐ 同族坑第二次上桌
- **现象**：CtrlC 精简版交付后用户二度打回"怎么还有最后 0.6s 尾部数字静音"。上一轮（§16，51.8s 事故）修的是"结尾静置段怎么响"，这一轮死尾从另一条路又回来了。
- **根因两层**：①CTA 追加句 s11 的 mp3 文件 5.208s，波形实测语音止于 4.414s——**尾部 0.79s 是 edge-tts 自带的静音垫**，追加脚本按文件时长写 end_frame=1733；②总长又按"尾句 end+18 帧"的旧公式多留 18 帧。语音 56.95s 讲完，片子跑到 58.41s，最后 ~1.4s 只剩垫乐残留（max -24dB，手机外放≈无声），听感即"数字静音"。
- **通用规则**：
  - **任何一句的 end_frame = 波形实测语音终点**（`silencedetect=n=-38dB:d=0.2` 取最后一段语音尾），mp3 文件时长/词级元数据一律只作参考——与"词级 offset 虚高"（§8）同族：**TTS 给的所有时间数字都要用波形校一遍**。
  - 成片 DUR = 语音终点 + ≤6 帧呼吸；要留静置段必须走 §16 的"垫乐叠尾音+≤1s 淡出"配方。
  - **修成片与修源码必须同一次做完**：ffmpeg 裁片的同时把组件 DUR 常量改掉（本次 1751→1715），只改一头=下次重渲 bug 复活。
  - **判"真死尾"看语音终点之后**：单抓末几秒的 silence_start 会把句间停顿/音乐间隙误判成死尾（02_代码如何运行 被这么误报过）；且**纯静音长度判不了"音乐淡出+短安静"（合格）和"残留垫乐渐升"（事故）的区别**——必须以人声响度为基准，看"可听声结束后剩什么"。已固化成 `scripts/qc_tail_silence.py`（人声基准 95 分位/可听级事件/淡出豁免三形态判定，校准样本见脚本头注释；阈值为三条实片校准所得，勿凭感觉改）。
- **修复实例（可复用）**：`ffmpeg -t <语音尾+0.2s>` CRF18 重编码裁掉死尾（刀口处实测 <-35dB，无爆音），PSNR 对比验证画质无损，末帧抽图确认完好；原始版留 out/ 存档。
