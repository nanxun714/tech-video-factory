# 渲染后质检清单（每条都是真实返工过的坑）

抽帧方法：cv2 顺序解码抽帧逐一目检，必抽点位 = **每个场景的结束帧**（元素应全部出现）+ **每个转场帧**（应为硬切新场景）+ **t=0 第一帧** + **结尾卡中途帧**。只查代码不看成片 = 未完成。采样清单用 `scripts/qc_auto.py` 自动生成（含 manifest）。

## 程序化预检（目检前必跑，2026-09-14 batch10 沉淀）

```bash
python <skill目录>\scripts\qc_precheck.py <视频.mp4> <纯ASCII输出目录> <SENT边界帧列表,逗号分隔>
```

输出 `<输出目录>/precheck.json` + 边界帧截图。**fail:false 才许进入目检和交付**；生产 agent 交付前必须自跑并把 JSON 贴进汇报，主会话用同一脚本独立复验。

四类自动断言（历史 bug 全部程序化）：
1. 边界帧与前一帧 diff<2 → 新场景没画出来（PageTurn bug 变体）
2. 边界帧 diff<4 → 无硬切=叠化转场（违反铁律①；HttpVsHttps 两轮人眼目检都没抓到，diff 扫描 10 秒抓到）
3. 边界帧灰度 std<12 → 大面积空白
4. 末帧 std<12 → 结尾卡空白/淡出

阈值依据：硬切边界实测 diff 6~13（InodeExhausted），叠化 0~4（HttpVsHttps）；背景高度共用的版式若误报可按实测微调阈值，但改前必须先人眼确认被 flag 的帧。
⚠️ cv2 随机 seek（`cap.set(POS_FRAMES)`）在 Windows 会抽错帧——HttpVsHttps 892 边界"假空白"即此假象，曾误判两次。抽帧一律顺序解码（qc_precheck.py / qc_auto.py 已内置）。

## §结尾段响度 + 主体具象性（2026-09-14 用户反馈返工沉淀，QC 必查两项）

### 音频：结尾段响度抽检（程序化，不许跳）
- **背景**：bed.wav 素材本体 mean -56dB，结尾截图卡静置 3.3s 全靠它=数字静音（-73.8dB），用户打回"进度条还剩3~4秒没声音"。详见 voice.md §音频素材响度。
- **检查**：`ffmpeg -ss <旁白结束秒> -i 成片 -af volumedetect -f null -`，mean_volume **≥ -45dB 为过**（合格线参考：实测修复后 -31dB，人声段 -25dB）。
- **量法备选（Remotion 内置 ffmpeg 未编 volumedetect 滤镜，CtrlC v2 实测）**：`npx remotion ffmpeg -ss <秒> -i 成片 -vn -ac 1 -ar 16000 -f wav 段.wav`，再 Python `20*log10(sqrt(mean(x²))/32768)` 算 mean dB，与 volumedetect 等效可比（实测结尾 -28.4dB/人声 -25.3dB）。
- **结尾静置段必须与最后一句话尾音重叠起播、时长 ~1s 内淡出（2026-09-19 用户打回"从51s就没声音"）**：两个坑叠加——①TTS MP3 实测时长含尾部静音，timeline 的 end_sec ≠ 语音实际结束帧（本片语音实际止于≈51.8s，end_sec=52.4s，中间 0.4s 实测 -77dB 纯死寂）；②3s 的 -27dB 结尾乐在手机外放=听不见。修法=bed_outro 起播帧压到语音实际结束前（与尾音叠 0.3~0.5s）、整段 ≤1s 快速淡出，量尾段逐 0.5~1s 分段响度（≥-45dB 只是底线，听感验收以"人声结束后不出现可测死寂"为准）。
- **建轴与成片总长：语音终点按波形实测，MP3 文件时长不可信（2026-09-19 CtrlC 精简版 0.6s 尾部数字静音，同类坑二次复发）**：edge-tts 每句 mp3 尾部自带 0.5~0.8s 静音垫（s11 实测文件 5.208s、语音止于 4.414s），上一轮 51.8s 事故已踩过一次，追加 CTA 句时又按文件时长建轴 + DUR=尾句end+18，死尾再次上桌。规则：①timeline 的 end_frame/end_sec = silencedetect 实测语音尾（`n=-38dB:d=0.2`），文件时长只作上限参考；②成片 DUR = 语音终点 + ≤6 帧呼吸，静置段走上一条的"垫乐叠尾音"配方；③**修成片与修源码必须同一次做完**——ffmpeg 裁片的同时改组件 DUR 常量（本次 58.41→57.17s 裁片 + ctrlcDurationInFrames 1751→1715），只改一头=下次重渲 bug 复活。
- **真死尾判定法（尾检脚本 `scripts/qc_tail_silence.py`，程序化不许跳）**：扫末几秒时单抓 silence_start 会误报——句间停顿/音乐段落间隙之后声音回来是正常的（02_代码如何运行 就被这么误报过）。脚本以片尾近 10s 的响度 95 分位为人声基准，定位"最后一个可听级声音"（≥基准-12dB），看它到 EOF 之间剩什么：**fail=可听声结束后 ≥0.5s 再无 ≥基准-8dB 的内容直到片尾**（画面挂着但没东西听，v4 事故形态）；**放行=可听级音乐淡出+≤2s 安静**的自然收尾（须有渐弱坡道，防"戛然而止接长静音"冒充，02 即此形态）；**warn=收尾 0.45~0.8s 或形态异常→必须人耳复听**。校准样本三条已在脚本头注释；损坏文件输出 verdict=error 转人工，批扫不中断。
- **对偶坑：拖尾（2026-09-19 batch10 十七条用户打回"话已经说完了，但是还有尾音"）**：与死尾正好相反——gen 脚本 TAIL_FRAMES=105（结尾卡停 3.5s）+ bed_outro（响度合格素材、0.35~0.4 音量）从 DUR-100 起 93 帧慢淡出直铺 EOF，每条话音落后拖 3.3~3.7s 可听垫乐（WiFi 实测 62.48s 话音落、66.8s 才完）。修法四件套：①建轴 TAIL_FRAMES=48（话音落+1.6s 收尾），gen_batch10.py 已改；②outro 只准"压句尾起播、≤1.5s 快淡"（CtrlC 精简版包络 [0,6,31,43]→[0,0.4,0.4,0]），禁恒定音量直铺 EOF；③成片返修配方=裁到语音终点+1.6s + `afade=t=out:st=<SP+0.15>:d=0.35,volume=0:enable='gte(t,<SP+0.4>)'` 挖除 outro + 重编 libx264 crf17（裁剪点必在 outro 起播前，否则它冒头）；④语音终点取 sXX.mp3 末段 **silence_start**（EOF 处 ffmpeg 补发的 silence_end=文件时长，含静音垫会虚长 0.5~0.8s，第一次批量返修就踩了）。返修后 `qc_tail_silence.py --speech-end <终点秒>` 拖尾断言：>2.6s fail / >2.0s warn。本次 18 条（含堆vs栈）已按此返修并同步源码 DUR/删 outro/Root.tsx 硬编码（HttpVsHttps），judge 36 帧全 pass。
- **修复配方（成片后处理，视频流无损、秒级，不必重渲）**：
  1. 生成响度合格的结尾音乐：`ffmpeg -y -i bed.wav -af "volume=40dB,loudnorm=I=-20:TP=-8" bed_outro.wav`
  2. 混入结尾段（**注意 adelay 陷阱：atrim 切出的段 amix 时从 t=0 对齐，不加 adelay 会混到片头**）：
     `ffmpeg -y -i 成片.mp4 -stream_loop -1 -i bed_outro.wav -filter_complex "[1:a]volume=0.4,afade=t=in:d=0.4,atrim=0:<段长s>,afade=t=out:st=<段长-0.7>:d=0.7,adelay=<起始ms>:all=1[a1];[0:a][a1]amix=inputs=2:duration=first:normalize=0[aout]" -map 0:v -map "[aout]" -c:v copy -c:a aac -b:a 192k 输出.mp4`
  3. 同步把 bed_outro Sequence 补进组件源码，保证下次重渲一致。


- **2026-10-27 终审新规（用户原话"可以了，你下次不要犯了"）：成片结尾禁加任何垫乐/收尾音**——bed_outro 整段叠法**作废**（素材本体自带 2s 渐强，人声结束后嗡声上爬再被片尾截断=用户听成噪音；且用户明确不要结尾音）。**结尾一律 = 语音终点 + ≤6 帧呼吸直接收（TAIL_FRAMES=6）**，总长宁短勿拖。此前"结尾静置段垫乐叠尾音"配方只在用户点名要垫乐时才用。案例：毕设01 两轮返工（先修渐强形状、再整段切除）才收敛到正确答案——**教训：用户没要求的音频元素一个都不加，"死尾"恐惧的正解是短尾不是补声**。
