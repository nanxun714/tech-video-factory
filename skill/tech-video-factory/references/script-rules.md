# SCRIPT 脚本规则详解

## 开头钩子

第一句同时禁一切铺垫词（2026-09-13 补）："大家好 / 今天讲 / 很多人 / 我们都知道 / 接下来 / 你有没有想过"全部剥掉——配音的第一个字就是冲突或反常识提问本身（"你16G电脑同时开30个程序，为什么不崩？"），起手式只用「人人见过的现象+反差疑问」或踩坑场景。

## 情绪密度 > 信息密度（完播率核心）

- 开头必须带"锐利感"——威胁感或利益感，如"面试问你这三个词，只背定义，面试官心里已经把你挂了"。太平/太像教科书/太像营销号都会触发用户防御心理
- 先答"潜台词"再答概念：讲 Docker vs 虚拟机，先说"面试官问这个是在试探你有没有真实排查经验"，再讲区别
- **每条视频至少埋一个"热经验"位**：真实踩坑案例/职场潜规则（如"上周有哥们配错这个，上线直接损失十万"）。脚本初稿用 `【踩坑案例位：待用户确认真实案例】` 占标，**必须等用户提供或确认真实案例后才能配音**——AI 不得编造具体损失金额/人名/公司

## 时长与密度

- 8 句左右、合计 250~320 字，弧线：钩子 → 潜台词 → 概念 → 原理 → 过程 → 总结
- **时长服务于内容，不为完播率数字砍时长**（2026-09-08 修正：早前"30 秒硬顶"作废，用户原话"不要为了完播率数字砍时长"）。开头第一秒上钩子、砍铺垫，但讲透的内容不许删
- 信息密度 4~6 字/秒；宁可超到 70s 也不许砍关键解释

## 结尾设计

- **结尾必须加"截图卡"**：最后 3 秒白底黑字总结图（口诀 + 两三行核心区别），完全静止停留 ≥3 秒——直接拉收藏率（当前收藏率低于同类 0.27% 中位数）
- **金句大字幕停留 ≥3 秒**（"502=后端挂了，504=后端跑太慢"级别的一句话结论），放慢节奏让人截图，不与底部字幕重复内容
- **合集导流**（排错/报错类长期价值题材适用）："关于 XX 排查，我还整理了另外 N 个常见报错，都在主页合集里，建议收藏"——与铁律 6 不冲突：写在结尾卡旁白里，和点赞 CTA 合成一次口播
- **中途不许口播"截图/收藏"引导**：结尾截图卡是唯一收藏 CTA（一个声音说一次）。中间想引导用视觉预告替代——角落贴"结尾有面试速查卡"小贴纸，不出声

## 结构节奏

- **第二断崖在 10 秒附近（2026-09-13 数据复盘）**：账号平均观看仅 9.28s——一半以上观众死在钩子和答案之间。前 2 秒钩子只管前 2 秒，**第 8~10 秒必须先兑现一半答案**（TCP 条标准结构：3s 抛问题 → 9s 亮出 TCP/UDP 双卡 → 30s 看机制演示）。脚本按"10 秒一兑现"排布，比单纯加快切换节奏有效

## 选题策略

- **对比类选题优先**：「两个技术点对比+一句话记忆口诀」是当前最优形式（Docker vs 虚拟机播放 5318、四条最佳）。**但吸粉靠"内容身份"不靠钩子（2026-09-13）**：代码运行全过程 5s完播全账号最低（18.6%）却吸粉 22 个，Docker vs VM 5s完播最高（33.7%）只吸粉 4 个——钩子决定播放量，选题内容决定关注。对比/排查/旅程三线轮换别全押对比，旅程类是吸粉主力

## 真实性

技术命令/名词必须真实，不确定就不写。
